# 동네사주카페 통합 서버

주문서 업로드 → 사주 계산 → 결제 → PDF/이메일 자동 발송까지 한 번에 처리하는
통합 서버입니다. Google Apps Script 주문서 업로드 앱과는 별도의 독립 서버입니다.

## 전체 흐름

1. 고객이 홈페이지(`index.html`)에서 주문서 양식을 다운로드해 작성
2. 작성한 엑셀을 업로드 → "운세를 만들고 있습니다" 팝업이 뜨는 동안 서버가
   실제 사주 계산(saju_engine)을 실행
3. 계산 완료 → "운세를 받아보시겠어요?" 팝업 → 확인 클릭
4. 결제수단 선택 페이지(`select-payment.html`)로 이동 → 토스/카카오페이/네이버페이 중 선택
5. 결제 완료 → 서버가 사주 계산 결과로 PDF 결과지를 생성
6. 생성된 PDF를 고객이 입력한 이메일로 즉시 발송 (+ 화면에서도 바로 다운로드 가능)
7. (문자 SMS는 아직 미연동 — 계정 준비되면 `mailer.js`의 `sendResultSms`에 연동)

## 폴더 구성

```
payment-server/
  server.js                  메인 서버 (업로드/주문/결제 API 전부 연결)
  orderStore.js               주문 저장소 (JSON 파일 기반, 실서비스는 DB로 교체 권장)
  sajuEngine.js                파이썬 사주 계산 엔진(saju_engine/)을 호출하는 브릿지
  fulfillOrder.js               결제 완료 시 PDF 생성 + 이메일 발송을 실행하는 공통 로직
  mailer.js                     이메일 발송 (SMS는 자리만 마련됨)
  saju_engine/
    run_saju.py                  사주 계산 CLI (생년월일시 -> 원국/오행/십성/대운 등 JSON)
    make_pdf.py                   계산 결과 -> PDF 결과지 생성 (LibreOffice 변환 방식)
    saju_core.py, saju_data.py, saju_analysis.py, saju_solar_terms.py,
    saju_interpretation_db.py      명리학 계산 로직 전체
  routes/
    toss.js, kakaopay.js, naverpay.js   결제사별 연동 (승인 완료 시 fulfillOrder 자동 호출)
  public/
    index.html                   메인 홈페이지 (업로드 + 팝업 흐름)
    select-payment.html           결제수단 선택 페이지
    payment-toss.html 등           결제사별 결제창/완료 페이지
    assets/주문등록_양식.xlsx        다운로드용 주문서 양식
  .env.example                  환경변수 예시 파일
```

## 로컬 실행 방법

```bash
cd payment-server
npm install
cp .env.example .env   # 아래 "필수 환경변수" 참고해서 값 채우기
npm start
```

브라우저에서 http://localhost:3000 접속 → 동네사주카페 홈페이지가 뜹니다.

## 필수 환경변수 (.env)

기존 결제 관련 값(TOSS_*, KAKAOPAY_*, NAVERPAY_*)에 더해 이메일 발송을 위한 값이 추가로 필요합니다.

```
# 이메일 발송 (예: 네이버 메일)
MAIL_HOST=smtp.naver.com
MAIL_PORT=465
MAIL_USER=your_id@naver.com
MAIL_PASS=네이버_메일_앱비밀번호
MAIL_FROM_NAME=동네사주카페

# 결제 발생 시 운영자에게도 알림 메일을 받고 싶다면 (선택)
NOTIFY_EMAIL=rlawowls2026@naver.com
```

네이버 메일은 "환경설정 > POP3/SMTP 설정"에서 SMTP를 켜고, 2단계 인증을 쓰는 경우
일반 로그인 비밀번호 대신 앱 비밀번호를 발급받아 `MAIL_PASS`에 넣어야 합니다.
Gmail을 쓴다면 `MAIL_HOST=smtp.gmail.com`, `MAIL_PORT=587`로 바꾸고 마찬가지로
앱 비밀번호를 사용하세요.

## 검증 완료 사항 (실제로 서버를 실행해 확인함)

- 홈페이지, 양식 다운로드, 결제수단 선택 페이지, 각 결제 페이지 모두 정상 로딩(200)
- 실제 주문서 엑셀(xlsx)을 업로드 → 파싱 → **실제 사주 계산 엔진이 원국표/오행/십성/
  대운/세운/신살까지 정확히 계산**하는 것을 확인
- 계산된 결과로 **7페이지 분량의 PDF 결과지가 정상 생성**되고, 한글이 깨지지 않고
  다운로드까지 정상 작동
- 결제 승인 시 **금액 위변조 방지 로직**(주문 금액과 다른 금액으로 승인 시도 시 차단) 정상 작동
- 이메일 발송은 `.env`에 메일 계정이 없을 때 **결제 자체는 실패시키지 않고 에러만 안전하게
  기록**하는 것을 확인 (메일 계정을 채우면 바로 실제 발송됨)

## 결제사별 준비 상태

- **토스페이먼츠**: 공식 테스트 키가 이미 `.env.example`에 있어 지금 바로 결제 테스트 가능
- **카카오페이**: 카카오 개발자센터에서 어드민 키 발급받아 `.env`에 입력하면 테스트 CID로 바로 가능
- **네이버페이**: 가맹점 심사 완료 후 키 발급 필요 (심사 전에는 예약 단계에서 인증 오류 발생이 정상)

## 다음에 이어서 할 수 있는 작업

1. **SMS(문자) 발송 연동**: 네이버 클라우드 등 SMS API 계정이 준비되면
   `mailer.js`의 `sendResultSms()` 함수 안에 실제 호출을 추가하면 됩니다.
   (`fulfillOrder.js`에서 이미 이 함수를 호출하도록 연결까지 되어 있습니다.)
2. **음력 생년월일 지원**: 현재는 양력만 지원합니다. 음력 입력 시 정확한 음력→양력
   변환 테이블 연동이 필요합니다.
3. **실서비스 전환**: 결제사 라이브 키 교체, HTTPS 도메인 적용, `orderStore.js`를
   실제 데이터베이스로 교체하는 작업이 필요합니다.
